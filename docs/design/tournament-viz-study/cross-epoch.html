This is the highest zoom-level — above any single tournament. The unit is the epoch: a short, ORDERED, linear chain, each epoch a frozen contract (board · brief · scoring · entrypoint · mutable_trees · proposer) plus a chosen tournament structure. The operator's question is not "who won this match" but "is the meta-loop making progress ACROSS contracts?" — which contract change helped or hurt, and where the loss floor reset when a new epoch rolled. These six options are structure-agnostic: structure is just one epoch attribute, and a structure-roll seam makes the best-loss comparison across it a soft one — every figure flags that seam rather than pretending the floor is comparable.

sample structure structure is a per-EPOCH attribute — this sets the structure the epochs run under + the E5 structure-roll target; the SAME six figures re-label the roll seam.

The sample · one realistic 6-epoch chain

Six epochs, linear lineage (v0_parent = prev_epoch:final_generation). Best-loss (the FLOOR — lower is better) descends overall but resets at two rolls: E3 changed scoring (a re-weight — the floor jumps because the metric itself moved), and E5 changed board + structure (harder board + a structure roll — the floor resets and the cross-roll comparison is SOFT). E1–E5 are closed; E6 is open / in-flight. Every option below renders this identical sample.

OPT 1 Loss-floor step chart + contract-change marker rail Floor resets are discontinuous events, not a smooth line — a step chart draws the floor as a held level that snaps at each roll; a color-coded vertical marker rail says which contract component changed there.

Reveals: the floor is a staircase, not a slope — it drops E1→E2, jumps UP at E3 (scoring re-weight, green rail tick) and again at E5 (board+structure, dashed SOFT seam), then resumes descending into the open E6. You read "progress" as net downward steps between resets, and the rail attributes every reset to a named contract change.

OPT 2 Handoff slope chart over the v0_parent seam The epoch→epoch handoff is a pairing: prev:final_generation → this:best. A slope chart makes each handoff one tilted segment — slope sign = did the new contract start from and then beat where the last one ended.
v0_parent (inherited start) ↘ this-epoch floor · one slope per handoff decision: did the contract change pay off from its inherited baseline
handoff improved (down slope) handoff regressed (up slope) v0_parent inherited level SOFT seam (structure roll)

Reveals: per epoch, the left dot is what it INHERITED (prev epoch's final gen), the right dot is the floor it REACHED. A steep down-slope (E2, E4, E6) = the contract paid off; an up-slope (E3, E5) = the new contract started worse and stayed worse than the inherited baseline — the re-weight / harder board cost floor. The structure-roll handoff (E4→E5) is drawn dashed: that slope is a SOFT comparison.

OPT 3 Contract-component heatstrip (epochs × components matrix) "What changed" is a small categorical matrix: epochs down, the 5 surfaced components (+ proposer) across. A heatstrip of changed/unchanged cells is the densest possible answer to "which lever moved each roll" — and exposes the proposer column the dashboard diff omits.
per-roll contract delta · filled = changed vs predecessor decision: which lever moved, and is the floor delta attributable to it

Reveals: scan a column to see how often each lever is pulled (board twice, scoring once, structure once); scan a row to read a single roll's whole delta. The right-edge floor-delta chip ties the change-set to the outcome: E3's lone scoring change → floor up; E5's board+structure pair → floor up + SOFT. The proposer column is shown explicitly with a note that the dashboard's contract-diff currently surfaces only the other five.

OPT 4 Icicle of the Epoch ⊃ Round ⊃ Generation hierarchy The corpus is a strict containment tree. An icicle sizes each epoch band by generation_count (how much work it absorbed) and colors it by best_scalar (how good a floor that work bought) — width = effort, hue = payoff, in one structure-agnostic shape.
epoch band width ∝ gen_count · hue ∝ best-loss · rounds & champion gen nested below decision: is effort buying floor, or is a big epoch a low-yield slog

Reveals: width tells you E5 absorbed the most generations yet stays reddish (a costly, low-yield slog after the harder board), while the slim E2 is deep green (cheap, big floor win). Drilling the nested row exposes each epoch's rounds and the single champion generation that set its floor. The structure-roll boundary is marked SOFT so you don't read the hue jump as pure regression.

OPT 5 Champion-lineage alluvial across the v0_parent seam Lineage is a flow: each epoch's champion seeds the next as its v0_parent. An alluvial ribbon makes the carry-over explicit — ribbon thickness = promoted_count carried, and the ribbon recolors / notches where a roll breaks comparability.
champion gen of epoch N flows in as v0_parent of N+1 · ribbon width ∝ promoted_count decision: is the lineage actually carried forward, or reset by a roll

Reveals: the unbroken chain of champion handoffs reads as a single river — you can see lineage is genuinely carried (not reset) even when the FLOOR resets. The ribbon thins where fewer were promoted (E3) and is notched/striped at the E4→E5 structure roll to say "the champion still flows forward but its loss isn't directly comparable across this seam."

A Gantt of lifetimes answers "how long did each contract run / which is still live"; a dumbbell docked to each bar pairs predecessor-floor ↔ this-floor so duration and floor-progress read in one row.

The two reset epochs (E3, E5) point the wrong way, and E5's dumbbell carries the SOFT-seam mark since its predecessor floor sits across a structure roll.
